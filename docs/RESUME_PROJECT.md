# 简历项目包装

## 1. 简历项目名称

基于 DeepSeek 的智能电商 Agent 系统

## 2. 一句话项目介绍

基于 Spring Boot + Vue + DeepSeek API 改造传统网上商城系统，构建覆盖用户端、商家端、仓储端的多 Agent 智能电商平台。

## 3. 技术栈

Java 17、Spring Boot 3、Spring MVC、MyBatis-Plus、MySQL、Vue 3、Vite、Pinia、Element Plus、ECharts、DeepSeek API、RAG、Maven。

## 4. 项目职责

1. 负责商城后端三层架构设计，实现商品、分类、用户、订单、购物车、评价等核心业务。
2. 负责 Vue 3 前端页面开发，实现商城前台、后台管理和 AI 工作台页面。
3. 负责 DeepSeek API 接入，封装统一 AI Service、异常处理、超时和降级策略。
4. 负责 ProductTool、OrderTool、UserTool、CommentTool、InventoryTool 设计，保证 AI 只基于真实业务数据回答。
5. 负责智能导购、智能客服、语义搜索、RAG 知识库、多 Agent 工作台等 Agent 功能实现。
6. 负责部署文档、Postman 接口集合、演示脚本和答辩材料整理。

## 5. 项目亮点

1. **低侵入 AI 改造**：AI 模块全部新增，不破坏原商城业务。
2. **Tool 调用封装**：Agent 不直接访问数据库，通过业务 Tool 调用已有 Service。
3. **多 Agent 编排**：统一工作台支持内容安全、意图识别、权限校验和 Agent 路由。
4. **RAG 知识库**：售后政策和平台规则问答基于检索片段，避免编造答案。
5. **可演示闭环**：支持商城浏览、导购、搜索、查单、RAG、文案、评论、订单分析、库存分析。

## 6. 可量化描述

- 设计并实现 15+ 个 AI Agent 能力，覆盖用户端、商家端、仓储端和通用治理端。
- 封装 5 类商城业务 Tool，统一商品、订单、用户、评论、库存数据访问。
- 初始化 70+ 商品、多个分类、用户、订单、评论和演示数据。
- 提供 Postman 集合和 Markdown 文档，覆盖核心 `/api/ai` 接口。

## 8. 面试讲解版本

这个项目不是单纯调用大模型聊天，而是在传统商城业务上做 AI Agent 改造。我先把商品、订单、用户、评论、库存封装成 Tool，Agent 只能通过 Tool 获取业务数据，不能直接查数据库。然后基于 DeepSeek 实现导购、客服、语义搜索、运营分析、库存分析和 RAG 知识库。最后用统一工作台做多 Agent 编排，先做内容安全审核，再识别意图、校验角色权限、路由到对应 Agent。

## 9. 面试常见问题与回答

### Q1：为什么不让 AI 直接查数据库？

直接查数据库有安全风险，也绕过了原业务校验。通过 Tool 调用已有 Service，可以复用权限、状态、逻辑删除等业务规则，并控制返回给 AI 的字段。

### Q2：如何避免 AI 编造商品？

Agent 的 Prompt 明确限制只能基于 Tool 返回的商品推荐；Java 侧先筛选候选商品，AI 只生成推荐理由，不允许新增商品名、价格和库存。

### Q3：RAG 为什么第一版不用向量数据库？

课程设计优先保证可运行和可演示。第一版用本地文档切片和关键词相似度，后续可平滑替换为 BGE + Milvus / PGVector。

### Q4：DeepSeek 调用失败怎么办？

每个 Agent 都有降级策略。例如导购返回规则推荐，RAG 返回最相关片段摘要，运营分析返回 Java 侧规则报告。

### Q5：多 Agent 工作台如何控制权限？

工作台根据用户角色限制可访问能力。USER 不能访问订单分析、库存分析等运营接口；MERCHANT、WAREHOUSE、ADMIN 按职责访问不同 Agent。
